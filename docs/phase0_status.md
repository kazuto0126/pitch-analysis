# Phase 0 handoff (2026-09-23)

The old source-acquisition work is saved locally on `integration/opencode-preprocessing`
at commit `4a65c32`. The analysis branch `codex/analysis-phase-0` starts from `bc29f48`.
Neither branch has been merged or pushed. Phase 0 introduces only local prepared-MP4
validation/working-copy standardization and an adapter over the existing analysis core.

Implemented:

- `pitch-input-v1` plus local schema validation, exact MP4/JSON pairing and no source URL fields.
- All-frame MP4 decode, metadata, checksum, CFR timestamp check, strict FFmpeg bitstream check.
- Optional local H.264/yuv420p working copy, preserving native FPS and frame count.
- `validate-pitch` and `analyze-pitch` CLI commands.
- Versioned initial per-pitch outputs; reserved schemas for later profile and comparison.
- Clean Python 3.12 `.venv-analysis`, fixed runtime/build dependency versions and a setup script.
- Current canonical release references updated to v0.6. Legacy commands and data remain.

Validation on this host:

- Clean Python 3.12.14 install from the pinned requirements succeeded; `pip check` passed.
- `python -B -m unittest discover -s tests -v`: 52 tests pass, including existing core tests,
  generated MP4 decode/standardization, corrupt input, contracts, handoff and actual MediaPipe
  model loading on a synthetic negative fixture.
- The real inference negative fixture reports `no_pose`, preserves an auditable timeline,
  and emits no fabricated events or metrics. It does not measure real pitcher pose accuracy.
- The historical `data/raw_videos/test_pitch.mp4` can be fully decoded but contains multiple
  pitches and is **not** a legitimate `pitch-input-v1` single-pitch example.
- One existing Yamamoto sample has header FPS 30.0297 but constant 30 FPS presentation
  timestamps. Validation now accepts it with a timing warning rather than calling it VFR.

Current limitations:

- The caller must supply correct identity, throwing hand, camera description and a genuinely
  prepared single delivery. Visual review is still required. Pose Landmarker uses one pose
  without explicit multi-person pitcher selection; that is Phase 1 work.
- Event frames are not generated by Phase 0. `events.json` is the existing review interface;
  `phases.json` and `analysis.json` describe initial preparation and do not auto-refresh
  after legacy revalidation. Profile/comparison schemas are reserved, not emitted.
- Existing tracked `.venv` and raw video history are retained pending a separate migration.
- The pinned lock is for Windows x64/Python 3.12 and pins versions, not wheel hashes. Other
  platforms require a separately validated lock.
