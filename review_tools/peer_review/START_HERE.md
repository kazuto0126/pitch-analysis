# 同學獨立覆核：從這裡開始

這份資料讓你在自己的電腦檢查投球影片中的既有骨架與動作事件。你的工作是看影像、記錄判斷；不需要安裝 Git、執行模型，或手動畫出整副骨架。

## 先開啟資料

1. 把收到的 ZIP **完整解壓縮**到一個資料夾，保留裡面的檔案與資料夾位置。
2. 雙擊資料夾最外層的 **`START_HERE.html`**，用 Edge 或 Chrome 開啟。
3. 在首頁確認每支影片的任務範圍，再進入該支的 `review_all.html`。
4. 用文字編輯器開啟該支資料夾的 **`REVIEW_NOTES.md`**，依下方流程填寫並儲存。

網頁、影片與逐格圖片都在資料夾內，可以離線使用。首頁不會自動儲存你的判斷；回覆請寫在 `REVIEW_NOTES.md`，或選擇填寫空白 `ground_truth.json`。

若瀏覽器阻擋本機影片，先確認 ZIP 已完整解壓縮，再換 Edge 或 Chrome。資料夾另附 `serve_review.py`，已有 Python 的人可在這個資料夾執行 `python serve_review.py`，它會開啟本機檢查頁；沒有 Python 也可直接看影片檔與 `frames/` 中的圖片。

## 你的任務範圍

首頁與各支 `REVIEW_NOTES.md` 的「指定任務」會寫明以下其中一種：

| 任務 | 要回覆的內容 | 完成時如何表示 |
|---|---|---|
| 完整獨立覆核 | 主體追蹤、六關節的全片區間、五個事件與整體觀察 | 全部檢查並填完後，才可表示完整覆核完成 |
| 事件補充 | 五個事件；至少回覆準備開始、最高抬腿與大致出手 | 表示事件補充已回覆；未檢查的關節與追蹤欄維持未覆核 |

請先自己看影像再填答案。包內的 `ground_truth.json` 是空白表，不包含其他人的判斷。

## 檢查順序

1. **先看完整原片。** 確認投手、身體側別、動作順序，以及哪些部位實際看得到。
2. **再看完整骨架影片。** 檢查骨架是否一直屬於投手，是否消失、跳動或大幅錯位。遇到問題要看前後影格。
3. **從頭至尾看逐格對照。** 左側是原片，右側是既有模型的原始骨架。接觸表適合找位置，判斷關節請打開全尺寸圖片。完整覆核要逐格檢查六關節；事件補充也要查看全片與各事件附近，不能只看被提示的區段。
4. **填回覆表。** 把相同判斷的連續影格合併成區間，記錄依據與不確定處。

影格從 **0** 起算，區間的開始與結束影格都包含在內。單一影格的開始與結束填同一個值。請以圖片上的影格編號為準；播放器暫停時間只適合找大致位置。

## 六個要檢查的關節

這批影片的投球側是**右側**，前腳側是**左側**。左右指投手自己的身體側別，與畫面左右不同。

| 關節 | 表內英文欄名 |
|---|---|
| 右肩 | `throwing_shoulder_reliability` |
| 右手肘 | `throwing_elbow_reliability` |
| 右手腕 | `throwing_wrist_reliability` |
| 左髖 | `lead_hip_reliability` |
| 左膝 | `lead_knee_reliability` |
| 左腳踝 | `lead_ankle_reliability` |

每個區間選一個狀態：

| 狀態 | 判斷方式 |
|---|---|
| `reliable`：可靠 | 原片看得到關節，骨架位置與可見位置合理相符 |
| `unreliable`：不可靠 | 原片看得到關節，但骨架錯位或漏點，位置無法信任 |
| `uncertain`：不確定 | 已看過，但影像模糊、重疊或邊界不清，無法決定 |
| `not_observable`：不可觀測 | 影像沒有足夠的位置證據，例如完全遮住或在畫面外 |

完整覆核中，六個關節各自都要從第一格覆蓋到最後一格，包含正常區間，不能只列異常。尚未看的區段不要當成可靠。

**被遮住的關節，不要用透視或想像補出位置。** 不需要填 X/Y 或 3D 座標，也不要把模型補點當成人工觀察。即使骨架在不可見的位置畫出點或線，也請依原片證據標成不可觀測，並在備註描述多餘或錯連的點線。

## 主體追蹤與整體問題

完整覆核要對下列項目各自回覆「全片已檢查且未見此問題」、「有問題區間」、「不確定／不可觀測」或「尚未檢查」。有區間就寫開始、結束、狀態與原因。

- **主體是否選對：** 有骨架時是否都屬於投手；若曾選到其他人，寫出區間。
- **換人（identity switch）：** 主要骨架明顯轉到另一個人。單個手腕錯連到旁人，未必代表整副骨架換人。
- **追蹤中斷（track break）：** 骨架消失或輸出中斷。骨架缺失本身不等於換人。
- **重大姿勢錯誤（major pose failure）：** 大部分骨架錯位、缺失或無法使用。
- **投球手臂遮擋：** 看不到的肩、肘或腕及其區間。只有看得出遮擋原因才寫為已確認；猜測原因請註明「推測」。
- **其他觀察：** 六關節以外的錯點、錯連、恢復位置或難判斷的情況。

自然遮擋可能讓某個關節不可觀測，但不一定是換人或整體追蹤失敗。不同問題的區間可以重疊。

## 五個動作事件

| 事件 | 請用這個定義判斷 |
|---|---|
| 準備開始 `preparation_start` | 本次投球動作開始的可見時點；若片頭已在動作中，說明開始在片外或無法確定，不要為了填表強迫填 0 |
| 最高抬腿 `leg_lift` | 左腿抬到最高處的時點；若最高位置維持數格，可填範圍。不是第一次腳離地 |
| 前腳落地 `foot_plant` | 左腳首次可見接觸地面附近；不要由骨架推測受力開始 |
| 大致出手 `approximate_release` | 球離開右手附近；優先查看最後仍在手中與首次在空中的影格，無法定位到單格就保留範圍 |
| 收尾結束 `follow_through_end` | 投球後動作完成並回復穩定或平衡附近；若片尾截斷，說明無法觀測 |

每個事件選一種填法：

- **確定單格（`annotated`）：** 填單一影格與判斷依據。
- **確定範圍（`annotated`）：** 填開始與結束影格，說明為何不能定位到單格。
- **不確定（`uncertain`）：** 寫原因；可以附候選範圍，但不要把候選值當成確定答案。
- **不可觀測（`not_observable`）：** 寫遮擋、片外或影像不足的原因，不假填影格。
- **尚未檢查：** 留空並說明未完成；留空不代表沒有問題。

每個事件的單格與範圍只能選一種。若球看不清楚，可以不確定或不可觀測；不用靠手腕骨架猜出精確出手格。

## 模型文字與人工信心

圖片下方與 `frame_index.csv` 的 `observed`、`interpolated`、`missing` 是**模型處理後狀態**，不是人工答案：

- `observed` 只表示模型資料通過既有條件，不保證關節真的可見或對位正確。
- `interpolated` 是模型補點，不能當成直接觀察的證據。
- `missing` 表示處理後資料缺失；右側原始骨架仍可能畫出點或線。

請以原片與前後影格做判斷，不要只相信模型 confidence。表內的 `confidence` 是**你自己的信心**，可填 0–1；不想量化可填 `null`，不必從模型數值複製。

## 交回什麼

最簡單是交回每支填好的 **`REVIEW_NOTES.md`**。請包含 reviewer 名稱或代號、實際檢查與提交時間及時區、影片 ID、任務範圍，並保留不確定處。

熟悉 JSON 的人也可填該支的空白 `ground_truth.json`，使用同一份 `ground-truth-v1` 格式。開始填寫時將 `annotation_status` 設為 `in_progress`，在 `provenance.reviewer` 填你的名稱或代號；不要修改 `source_video`、來源雜湊、影格數與固定格式欄位。完整覆核的 JSON 只有在所有必要欄位、六個全片區間及五個事件都已回覆時才設 `reviewed`，並填實際完成 UTC 時間。事件補充維持 `in_progress`、完成 UTC 時間為 `null`，未檢查的關節與追蹤欄保持 `null`。

把回覆交給提供資料的同學即可，不必重傳影片或圖片，也不需要使用 Git。收到的文字判斷會由專案維護者整理、驗證後，另存成你的獨立覆核版本。與其他人的分歧會保留，之後由人一起回看影像處理。
